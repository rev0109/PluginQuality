Issue 1

rule_08 - nullptr After Release
Status: ❌ VIOLATION | File: XCast.cpp | Line: 149

What's wrong: The member pointer is used for Release(), but it is not cleared immediately. Later teardown work occurs before it is set to nullptr at line 163, leaving a dangling member if the release destroys the object.

Code found:

// XCast.cpp:149
VARIABLE_IS_NOT_USED uint32_t result = _xcast->Release();
// XCast.cpp:163
_xcast = nullptr;

Fix:

uint32_t result = _xcast->Release();
_xcast = nullptr; // clear the member immediately after Release()

Status: ❌ VIOLATION | File: XCastImplementation.cpp | Line: 190

What's wrong: Configure() acquires PowerManager, then the manager, SystemServices, AppManager, and AppActions. Deinitialize() unregisters PowerManager first and releases the interfaces in forward acquisition order, rather than unwinding them in reverse.

Code found:

// XCastImplementation.cpp:341-345

Initialize(service...);

InitializeAppManager(service);
InitializeAppActions(service);
// XCastImplementation.cpp:190-195, 207-224

unregisterNetworkEventHandlers();
unregisterSystemEventHandlers();
// ... then releases PowerManager before later-acquired interfaces.

Fix:

// Stop callbacks and release in reverse acquisition order:
unregisterAppManagerEventHandlers();
unregisterSystemEventHandlers();
unregisterNetworkEventHandlers();
unregisterPowerEventHandlers();
// Then release AppActions, AppManager, SystemServices, NetworkManager, and PowerManager.
