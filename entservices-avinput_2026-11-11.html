Detailed Findings

Issue 1: Duplicate plugin registration

rule_15 - Plugin Metadata Registration
Status: ❌ VIOLATION | File: AVInput.cpp | Line: 36, 49

What's wrong: The same AVInput class is registered once through Plugin::Metadata and again through SERVICE_REGISTRATION. These are competing registration mechanisms for one class.

Code found:

// AVInput.cpp:36,49
static Plugin::Metadata<Plugin::AVInput> metadata(...);
SERVICE_REGISTRATION(AVInput, API_VERSION_NUMBER_MAJOR, API_VERSION_NUMBER_MINOR, API_VERSION_NUMBER_PATCH);

Fix: Keep one registration mechanism for AVInput; retain the separate SERVICE_REGISTRATION(AVInputImplementation, ...) for its implementation class.

rule_24 - Constructor Must Be Empty
Status: ❌ VIOLATION | File: AVInput.cpp | Line: 57

Issue 4: Unsynchronized lifecycle state

rule_47 - Shared State Protected by CriticalSection
Status: ❌ VIOLATION | File: AVInput.cpp | Line: 78, 342-344

What's wrong: Initialize()/Deinitialize() assign and clear _service and _connectionId, while Deactivated() reads both on a remote-connection callback. No common lock or atomic protects this access, so callback and teardown can race.

Code found:

// AVInput.cpp:78,342-344
_service = service;
if (connection->Id() == _connectionId) {
    ASSERT(nullptr != _service);
    Core::IWorkerPool::Instance().Submit(..._service...);
}

Fix: Synchronize the shared lifecycle state and prevent the callback from submitting work after teardown has started; unregister callbacks before releasing the service.

⬆ Back to Issue Summary

Issue 5: Stored IShell pointer lacks ownership

rule_56 - COM Reference Counting Correctness
Status: ❌ VIOLATION | File: AVInputImplementation.cpp | Line: 139

What's wrong: Configure() stores the borrowed IShell* in a member without calling AddRef(). The pointer's lifetime is therefore not owned by the implementation.

Code found:

// AVInputImplementation.cpp:139

Fix: Remove the unused member assignment, or retain the pointer with a balanced AddRef()/Release() pair and clear it when configured with nullptr.

Issue 6: Concurrent handlers share unprotected state

rule_58 - JSON-RPC Handlers Are Re-entrant Safe
Status: ❌ VIOLATION | File: AVInputImplementation.cpp | Line: 545, 590, 592, 1019, 1634

What's wrong: JSON-RPC operations update planeType and isAudioBalanceSet, while event callbacks read those values. Concurrent requests also mutate shared volume fields. These accesses do not use _adminLock or another common synchronization mechanism.

Code found:

// AVInputImplementation.cpp:545,590,592,1019,1634
planeType = plane;
planeType = -1;
if (isAudioBalanceSet) { ... }
ParamsType params = std::make_tuple(port, locator.str(), status, planeType);
isAudioBalanceSet = true;

Fix: Protect the shared state consistently (or make independent flags atomic) and take a local snapshot before building callback payloads.
