Issue 7

rule_42 - Observer Locking
Status: ❌ VIOLATION | File: DisplaySettings.cpp | Lines: 5117, 5785-5789

What's wrong: Subscribe paths append event names to m_clientRegisteredEventNames without m_callMutex, while teardown iterates and clears that same vector under the mutex. Concurrent subscription and deinitialization can race or invalidate the iteration.

Code found:

// DisplaySettings.cpp:5117
m_clientRegisteredEventNames.push_back(eventName);

// DisplaySettings.cpp:5785-5789 (under m_callMutex)
for (std::string eventName : m_clientRegisteredEventNames) {
    m_client->Unsubscribe(1000, _T(eventName));
}
m_clientRegisteredEventNames.clear();

Fix: Use one synchronization policy for every list mutation and snapshot the names before performing remote unsubscribe calls.

std::vector<std::string> names;
{
    std::lock_guard<std::mutex> lock(m_callMutex);
    names.swap(m_clientRegisteredEventNames);
}
for (const auto& name : names) {
    m_client->Unsubscribe(1000, _T(name));
}
