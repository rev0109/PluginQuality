Validation Summary

AVInput is a Thunder plugin exposing an AV-input API over JSON-RPC/COM-RPC, with a separate implementation that talks to DeviceSettings and dispatches notifications. This review found 9 confirmed, 7 partially valid, 3 false positives, and 2 needing more context. The strict false-positive rate is 3/21 (14.3%); partial findings are not counted as false positives. Confirmed findings are mostly maintainability or concurrency concerns; the strongest demonstrated risks are unsynchronized shared state and subscriber callbacks invoked while _adminLock is held. (AVInput.cpp:82; AVInputImplementation.cpp:300; AVInputImplementation.cpp:1574)

The advisor usefully located real code patterns and the two dispatch-lock findings are supported. It also overstates several findings: metadata and SERVICE_REGISTRATION occur together in the local plugin guidance example, while the local legacy config uses autostart and the external API details are not part of this checkout. (AVInput.cpp:36; AVInput.cpp:49; AVInput.conf.in:1)

Regression risk: A lock held across framework calls or callback waits may deadlock. Keep critical sections short and test shutdown ordering.

Reproduction: Disconnect the remote implementation concurrently with plugin deactivation. Expected no access to released/cleared state; deterministic reproduction requires Thunder runtime.
